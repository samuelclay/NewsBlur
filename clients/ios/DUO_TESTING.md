## Device Hub workflow

Reuse the booted simulator. Device Hub supplies the closed, partial, and open poses and rotation controls. On this machine the standard computer-control connection timed out; macOS scripting was explicitly authorized to operate Device Hub.

The outer and inner simulator displays have different screenshot IDs. Use `IOS_SIM_DISPLAY=1` for the outer display and `IOS_SIM_DISPLAY=3` for the inner display with `run_ios.py screenshot`. An inactive display can produce a black image; that does not by itself indicate an app rendering failure.

The existing `idb` input helper cannot load SimulatorKit from Xcode 27.1. System Events crashes on pointer input on this Mac. The user also authorized direct pointer/keyboard events; these now operate Device Hub after explicitly activating its window. The open pose was visibly verified before run 33. Capture fresh window bounds before converting screenshot coordinates to desktop points.

When returning focus to Device Hub, the first click inside the simulated device can only activate its window. Focus the window using its blank title bar before interacting with the app. A no-shadow window capture resized to the window's point dimensions avoids ambiguity from Retina screenshot scaling. Bounded native accessibility reads also expose Device Hub's menus even though the broad computer-control window read times out.

Xcode 27.1 also exposes simulator rotation through `xcrun devicectl device orientation get|set --device <UDID>`. During the locked-session audit, `set landscapeLeft` reported success but an immediate `get` still returned portrait; screenshots also remained portrait. This is not successful rotation coverage. The installed XCTest and devicectl interfaces do not expose a corresponding fold-pose operation; changing screen geometry is not equivalent to folding the device.

Run the Alpha tests on this same simulator with `-parallel-testing-enabled NO`. For deliberately failing reproductions, `-collect-test-diagnostics never` avoids lengthy simulator diagnostic collection after the assertions finish.

`NewsBlurAlphaUITests` depends only on Alpha. Its opt-in `Test_DuoLiveUI` class activates the existing account without fixture launch arguments: set `TEST_RUNNER_NEWSBLUR_LIVE_DUO_UI_TESTS=1` and select `-only-testing:NewsBlurAlphaUITests/Test_DuoLiveUI` with the `NewsBlur Alpha` scheme. The existing `ReaderUITests.swift` and `AddSiteUITests.swift` also compile into this Alpha UI target for isolated conventional-device fixtures. Do not combine the production NewsBlur UI-test target dependency with Alpha in a temporary scheme: both application targets emit the `NewsBlur` Swift module.
