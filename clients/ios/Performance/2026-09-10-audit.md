# iOS scrolling audit, September 10, 2026

Worktree: `ios-scroll-performance`. Runtime: NB Alpha, iPhone 17e simulator, iOS 26.5, the existing `samuel` account. Mark-as-read-on-scroll is enabled. The standard native story list retains its titles, previews, thumbnails, feed colors, metadata, intelligence indicators, related-story rows, and read-state dimming.

## First measured iteration

Both builds use Alpha Release with the existing Objective-C optimization setting (`-O0`). The baseline app was preserved before the production fixes. Measurements run with video recording, symbolized CPU sampling, and the opt-in display-link/cell probes described in [README.md](README.md).

| Feed cell configuration p95 | 1.324 ms | 1.218 ms |
| Feed drawing p95 | 1.230 ms | 1.192 ms |
| Folder header drawing p95 | 3.910 ms | 2.953 ms |
| Feed main-thread frame gaps | 7 / 1,262 | 4 / 1,269 |
| Story cell configuration p95 | 1.139 ms | 1.212 ms |
| Story scroll-to-read callback mean | 0.223 ms | 0.078 ms |
| Story height callbacks | 4,461 | 1,593 |

| Detail gradient updates | 5,843 | 1,332 |
| Detail main-thread frame gaps | 11 / 860 | 11 / 915 |
| Detail worst main-thread frame gap | 39.965 ms | 32.341 ms |

Feed and title runs use 24 gestures with seeds 417 and 812. Detail uses 16 gestures with seed 213 on the same TechRadar full-text article (`7564:efaf71`). The after detail article was located through search, so the neighboring articles differ. Live unread story lists also change as scrolling marks stories read and new stories arrive; these are production-shaped runs, not identical immutable datasets. The controlled regression benchmarks supplement the videos. A frame gap here means a main-thread callback interval above 1.5 times its requested interval, not a GPU presentation measurement.

The first iteration removes unnecessary SwiftUI story-model reconstruction from the native list, avoids reloading cells just to update scroll-read state, caches rendered custom icons, and avoids redundant detail toolbar/adjacent-page updates. The thumbnail path retains its existing bitmap during refresh and deduplicates image requests while retaining changed-source, empty-source, retry, and obsolete-response behavior.

All 38 first-iteration regressions passed. The 300-render custom-icon microbenchmark fell from approximately 84 ms to 0.94 ms. Pixel comparisons check cached custom icons against fresh drawing across icon types, sizes, and appearance changes.

The feed improvement was modest. The after CPU profile still sampled synchronous favicon disk reads during cell configuration. A read-only audit of the actual cached archives found 651 images totaling approximately 64 MB decoded, including 42 images at 384×384 pixels. Warming all originals into a 5 MB memory cache creates churn. The next feed experiment uses the existing rounded artwork at its displayed resolution, retaining originals for larger uses.

## Second comparison and targeted follow-ups

The second comparison retains the original build and uses the same gesture seeds, counts, native layout, preview settings, and mark-on-scroll preference. Both detail runs now open the same article through the same search results, so neighboring pages match as well.

| Feed cell configuration p95 | 1.211 ms | 1.501 ms |
| Feed drawing mean | 0.522 ms | 0.292 ms |
| Feed main-thread frame gaps | 5 / 1,288 | 8 / 1,266 |
| Story scroll-to-read callback mean | 0.213 ms | 0.083 ms |
| Story main-thread frame gaps | 54 / 1,192 | 14 / 1,260 |

| Detail gradient updates | 5,992 | 1,431 |
| Detail main-thread frame gaps | 13 / 915 | 10 / 920 |
| Detail excess frame-gap time | 135.759 ms | 118.540 ms |

Feed cell work decreased, but frame gaps did not consistently improve. One 100.662 ms gap included 82 cell configurations taking 71.280 ms, followed by 85 draws taking only 1.564 ms. The table hides descendant and duplicate parent rows with a zero height, while its cell construction omitted fewer cases. It was preparing full cells and loading icons for invisible rows. A regression reproduced 100 hidden rows causing 100 favicon reads; the third iteration returns the existing blank cell and skips prefetch for those rows. Positive-height artwork and search behavior remain covered.

Controlled tests also compare appending 12 stories at increasing list sizes:

| Existing stories | Original reload | Guarded insertion | Insertion with cached row heights |
| --- | ---: | ---: | ---: |
| 100 | 17.06 ms | 3.45 ms | 2.80 ms |
| 1,000 | 144.85 ms | 11.42 ms | 6.87 ms |
| 5,000 | 722.35 ms | 44.14 ms | 23.20 ms |

At 5,000 stories, preview normalization falls from 5,012 stories to 12. Tests check existing cell content, cluster mappings, scroll position, read-on-scroll anchor, filter/layout changes, empty and fully hidden pages, and full story-content replacement after sharing. The remaining 15.53 ms in this synthetic case is model traversal.

Read/unread model replacement at the end of a 5,000-story list falls from 4.270 to 0.767 ms per change, preserving collection snapshots and legacy identifier handling. Warm detail HTML preparation falls from 3.689 to 1.110 ms per page. Repeated bundled asset reads fall from 120 to zero over 12 draws across three controllers, with byte parity for all four themes, five scripts, embedded fonts, and changing dynamic content. The existing WebKit navigation/reveal sequence is unchanged in that iteration.

All 92 third-iteration tests pass. Additional thumbnail tests reproduce and fix removal-versus-promotion races, plus same-URL freshness after explicit refresh/account reset while retaining displayed images.

Cold-launch profiling is intrusive: CPU-sampled runs reached their first feed cell at 3.73–4.03 seconds from the launch request. Controls without CPU attachment reached it at 1.452 seconds originally and 1.469 seconds in the third build (probes ready at 0.746 seconds, view-controller preparation 316 ms). These changes do not establish a cold-start improvement. Treat the sampled startup numbers as diagnostic evidence, not ordinary launch performance. A recorded warm All Site Stories opening took 762 ms from the automation checkpoint to first cell configuration; this is not a full-image/web-content completion measurement.

## Repeated feed runs and longer story stress

Warm feed repeats use the second pass through the same process, with seed 417 and 24 gestures:

| Measurement | Original warm run 4 | Third fixes warm run 4 |
| --- | ---: | ---: |
| Feed cell configuration mean | 0.222 ms | 0.201 ms |
| Feed cell configuration p95 | 0.472 ms | 0.436 ms |
| Feed drawing mean | 0.482 ms | 0.347 ms |
| Feed main-thread frame gaps | 5 / 1,258 | 2 / 1,257 |
| Feed excess frame-gap time | 98.735 ms | 33.398 ms |

First-pass sampled run 3 was inconsistent: the original had five gaps with an 83.531 ms maximum; the third build had seven gaps with a 232.176 ms maximum. The latter contains a single 209.992 ms feed drawing event whose exact cause is unresolved. It is retained in the evidence, rather than excluded from the comparison.

A repeat with CPU sampling disabled (`*-feeds-no-sampler-05`) had mean cell configuration of 0.478 to 0.238 ms, mean feed drawing of 0.433 to 0.263 ms, five to four gaps, and maximum gaps of 82.775 to 40.458 ms. The 232 ms outlier did not recur. This control does not prove that sampling caused that particular outlier. Identical gestures can traverse different numbers of rows when deceleration and asynchronous feed refresh differ.

The third short title run had 25 gaps in 1,113 intervals and a 35.664 ms maximum. Its longer 100-gesture run (seed 9001) rendered 769 cells at 0.337 ms mean / 1.140 ms p95. It had 65 gaps in 5,029 intervals, a 124.920 ms maximum, and 47 full reload callbacks averaging 14.429 ms with a 38.020 ms maximum. The CPU profile identifies `fetchRiverPage:withCallback:` calling the initial `loadingFeed` presentation on every page. That schedules immediate and delayed full reloads through `changedLayout`, despite the guarded insertion in `renderStories:`. A separate regression and fix retain the presented native list while requesting a later page.

The worst long-run gap contains a 68.275 ms content drawing event. Aggregated CPU samples point to title measurement and first-use CoreText font fallback, but cannot attribute an individual timed event to a particular story. Component probes will distinguish title measurement, text drawing, and image drawing before choosing another rendering change.

Third detail run 3 retained a previously saved reading position, so its 12 gaps / 767 intervals are not a matched starting-position comparison. The separate `before-detail-navigation-04` recording reopens the same full-text article three times from the top, without CPU sampling, as the reference for the single-navigation experiment.

## River presentation fix and exact text-layout diagnosis

The next candidate skips the initial loading presentation for subsequent pages of an existing native river list. Sixteen pagination tests pass, including the new regression and non-native/daily-briefing preservation cases. The new regression fails against the preceding binary. The short run records no full reloads across 11 responses, down from 16 reloads in the preceding short run.

| 100 gestures, seed 9001 | Third fixes | River presentation fix |
| --- | ---: | ---: |
| Full story-list reloads | 47 | 0 |
| Story height callbacks | 17,807 | 6,572 |
| Cell configuration p95 | 1.140 ms | 1.074 ms |
| Page rendering callbacks | 24 | 23 |
| Main-thread frame gaps | 65 / 5,029 | 17 / 5,066 |
| Excess frame-gap time | 1,158.572 ms | 299.602 ms |
| Worst main-thread frame gap | 124.920 ms | 68.455 ms |

The live unread dataset changes between runs. The comparison preserves gesture seed/count, layout, previews, images, and mark-on-scroll behavior. `stress-titles-04` contains the later video, sample, component events, and summary.

At 49.2346 seconds into that long run, preview measurement takes 59.784 ms inside a 60.627 ms content draw, immediately followed by the 68.455 ms frame gap. The title measurement before it takes only 0.050 ms. The other measured drawing components total less than 1 ms. The symbolized CPU profile locates fallback-font loading and OpenType CID parsing inside the preview `boundingRect` call. This supports preparing the exact upcoming text layout before visibility, while retaining the existing typography and drawing.

The new short run (`after-titles-04`) has five gaps in 1,089 intervals, including a separate 324.698 ms outlier at 0.727 seconds. No long cell/drawing/layout/reload event overlaps it, and all five gaps occur within the first 1.84 seconds. The aggregate sample does not establish its cause. It remains in the report as an unexplained startup-of-scroll outlier.

First-page loading regressions are recorded in `fourth-firstpage-clean-before.xcresult`: ten tests produce ten expected assertion failures with no unexpected failures. The preceding mixed run (`fourth-before.xcresult`) also includes three fixture crashes from dereferencing an absent array; those fixtures were repaired before the clean reproduction. Article navigation regressions separately produce 13 expected assertion failures across 11 tests in the original two-navigation implementation. The preliminary single-navigation candidate passes the navigation identity and stale scroll-restoration checks; modal-return and actual WebKit resource-stall validation remain in progress.
