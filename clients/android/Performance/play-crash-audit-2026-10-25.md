# Android Play crash audit, October 25, 2026

Play Console confirmed production **16.0.4 (296)**. The Reporting API inventory covers **September 27 through October 25, 2026**, with no version, foreground, or user-perceived filter. All issue pages were consumed: **78 groups / 1,204 events** (43 crash groups and 35 ANR groups). We retrieved up to three deduplicated examples per group and additional current-version samples for the tablet and Chromium groups. This is a 28-day inventory, not all historical events.

A second query restricted to version 296 returned **21 groups / 99 events: 13 crash groups / 83 crashes and 8 ANR groups / 16 freezes**. Counts are report events, not unique users. Play Console's user-perceived totals and freshness differ from the unfiltered API interval.

## Samsung tablet report

Play group `48795fc66cc0c7ed2f5a49885c72418b` has a **Samsung Galaxy Tab S7, Android 13 / API 33, version 296**, sample from October 23. Its toolbar navigation calls `StorySplitView.prepareFeedList`, which unconditionally invoked `invalidateVisibleActivityStacks`. That method throws on Window SDK extensions below 3. Group `8aa345b469f8a149d754901ffb1e5d41` shows the same cause during activity resume/startup, with a Lenovo Android 13 tablet sample. Together these groups account for **52 current-version crashes**.

This closely matches the email, but the available sample says Tab S7, not S7+, and cannot identify the sender. API-level/extension regressions reproduce the failure; physical smoke testing used the already attached Galaxy Tab A8 running Android 14, not an Android 13 Tab S7+.

## Validation and limitations

- F-Droid compatibility: `./gradlew -Pfdroid :app:compileDebugUnitTestKotlin` passed, including the shared source and tests. This was compilation, not an executed F-Droid test suite.
- Installed final debug APK on the existing Samsung Galaxy Tab A8 (SM-X200), Android 14. Login was preserved; feed sync, article reading, back navigation, light/dark/black/sepia rendering passed smoke checks. Arabic and Hebrew reader layouts were inspected in the isolated storecapture variant.
- Native resource check against the installed APK passed **315 plural-formatting cases across all 21 languages**.
- Final Play unit suite: **909 tests, zero failures, errors, or skips**. Debug and isolated storecapture APKs built successfully.
- `localization/manage.py translate --budget 2`, `check`, and `compile` completed in Docker. All supported translation catalogs have zero missing messages. No language selector or detection logic changed.
- Native SQLite proof ran in a temporary shell process using an in-memory database, without modifying the logged-in app's data. The tablet's default cursor window did not reproduce; setting an explicit 2 MiB window reproduced the device-dependent limit before validating the scalar query.
- Regression tests establish each fix's failure condition. ANR fixes remove demonstrated blocking paths; timing impact in production remains unmeasured.
- Five current crash groups remain unresolved: two Chromium wrappers without messages/app frames, one OOM, one RecyclerView mismatch without adapter details, and one native runtime signal. Seven current ANR groups remain unresolved. No broad exception swallowing or speculative rewrites were added for these.
- OOM reports show allocation failure while loading story clusters, but no heap/payload evidence. Overlapping reader loads are a plausible memory amplification risk, not an established root cause.
- Several older groups were already fixed. The table below distinguishes those from new repairs and insufficient-evidence reports. Matching `15.1` R8 mapping hash `daa84c02585a75793d971d8b51f07a2179e46680b7eced383f474024b6a23ea5` resolved historical obfuscated snackbar, icon-table, and Hilt-widget frames.

## Publication boundary

At the end of the investigation, source fixes were committed locally on the existing `main` branch. The user subsequently authorized pushing and a patch release. All fixes were pushed and included in [Android 16.0.5 (297)](../releases/16.0.5/README.md), submitted October 25 for full production rollout.
