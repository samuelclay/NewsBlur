Play Console showed a 3.71% crash rate for the last 28 days, up 2.355 percentage points. That aggregate is not the crash rate of the latest release. The live production page showed 15.1 available, 16.0 halted, and 16.0.1 in draft.

The investigation initially enumerated 166 historical crash/ANR groups using the Reporting API with no version or foreground-only filter. Following the requested scope refinement, fixes focus on current code and recent reports. The recent API request used start 2026-10-14 and end 2026-10-17 21:00, without a timezone field (the API rejects timezone/UTC-offset arguments). All pages were consumed: 18 issue groups, 117 events, and 28 sample reports. These are 10 crash groups and 8 ANR groups; users can occur in multiple groups.

## Verified earlier fixes

- The folder-navigation overflow occurred on version 281. Current code uses bounded traversal, fixed by `553b13981` / `25b30d0a3` and covered by `SessionDataSourceTest`.
- The RecyclerView position failure occurred on versions 289–290. Version 291 includes `8982276e0`, which makes free-account preview rows and diff notifications agree; `Test_StoryViewAdapterSubscriptionPreview` covers that mismatch. This addresses a known cause of the signature; the stripped stack does not establish every historical occurrence had that cause.

## Source changes and evidence

- **Database startup:** database schema 11 creates a missing custom-icon table without deleting cached articles, queued actions, existing icons, or cluster receipts. Six tests execute the production migration against real SQLite and failed before the repair. Play removes the original SQLite exception messages, so the historical cause of table loss is not established.
- **Unread indicator:** the reader root is a CoordinatorLayout; its snackbar cannot use FrameLayout layout parameters. The original crash was reproduced by tapping the indicator on the logged-in Samsung S22 running 15.0.5. Tests also retain the existing anchor, margins, and palette across light, dark, black, and sepia.
- **Logging:** the supplied stack explicitly fails in Android external-cache lookup during a WebView process startup. Logging now falls back to internal cache for the observed null-pointer failure or denied storage access.
- **Sync lifecycle:** when dependency injection fails, service shutdown previously accessed an uninitialized property. Tests cover shutdown cancellation, normal idle-state notification, and job stopping before injection.
- **Saved state:** expanded historical examples in the same serialization group explicitly name android.os.Handler. Mark-read confirmation saved an Activity callback in its Bundle. The regression reproduces that Handler serialization failure. Dialog state now stores only whether to notify the current host, preserving the original no-callback behavior.
- **Related serialization defects:** full Story objects saved by share/reply dialogs can contain Reply objects, which were not Serializable. Classifier maps restored by Gson relied on its internal LinkedTreeMap serialization hook, which release shrinking can remove. Tests exercise nested story roundtrips and require platform-serializable classifier maps; these are additional proven source defects, not claims that every Play sample identifies these classes.

## Reports without a proven fix

All eight recent ANR groups remain explicitly unresolved. Most Android 37 samples stop inside framework queue operations or coroutine startup and do not establish which operation caused the timeout. One sample has no stack. The Chromium group likewise lacks an exception message or application frame, including the extra historical examples retrieved. No speculative exception suppression or global coroutine rewrite is included.

## Release boundary

This PR prepares source fixes and validation. It does not publish an Android release or establish that production crash rates have fallen.
